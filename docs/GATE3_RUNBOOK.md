## روز ۰ — راه‌اندازی یک‌باره (حدود ۲۰ دقیقه)

### گام ۱. ربات بسازید (۵ دقیقه)

1. در تلگرام به **@BotFather** بروید → `/newbot`
2. یک نام بدهید (مثلاً «XGPedia Bot») و یک username (مثلاً `xgpedia_bot`)
3. توکن را کپی کنید — چیزی شبیه `123456789:AAE4...`

### گام ۲. کانال بسازید (۵ دقیقه)

1. کانال عمومی جدید بسازید (مثلاً XGPedia)
2. شناسهٔ آن یکی از این دو است — هر دو کار می‌کند:
   - **@username** عمومی کانال (ساده‌تر؛ همین را در `.env` بگذارید)، یا
   - شناسهٔ عددی `-100...` (با ربات‌هایی مثل @username_to_id_bot قابل دیدن است)
3. ربات را **ادمین کانال** کنید: Channel → Administrators → Add admin →
   username ربات → تیک «Post Messages» روشن بماند

### گام ۳. شناسهٔ عددی خودتان (۲ دقیقه)

به **@userinfobot** پیام بدهید؛ عدد `Id` پاسخش همان `ADMIN_TELEGRAM_IDS` است.

### گام ۴. `.env` را پر کنید (۲ دقیقه)

```
TELEGRAM_BOT_TOKEN=123456789:AAE4...     # از گام ۱
TELEGRAM_CHANNEL_ID=@xgpedia_channel      # از گام ۲
ADMIN_TELEGRAM_IDS=123456789              # از گام ۳
```

### گام ۵. حیاتی: ربات را start کنید (۱ دقیقه)

از **حساب خودتان** به ربات پیام `/start` بدهید. ربات نمی‌تواند به کسی پیام
بدهد که او را start نکرده باشد — پرتکرارترین خطای روز صفر همین است.

### گام ۶. بررسی فقط-خواندنی (۳۰ ثانیه)

```
python run.py check-telegram
```

هیچ پیامی ارسال نمی‌شود؛ فقط توکن، کانال، ادمین‌بودن ربات و دسترسی به
ادمین‌ها چک می‌شود. باید آخر خط بنویسد **`all green`**. اگر قرمز داشت → جدول
عیب‌یابی پایین همین سند.

## روز ۱ — اولین پست (dry-run → انتشار واقعی)

```powershell
python run.py daily                 # زنجیرهٔ کامل: sync → پست‌های فردا → رندر → صف تأیید
python run.py list-posts            # شمارهٔ پست‌ها (post_id) را ببینید
python run.py publish --post-id 1 --dry-run    # کارت فقط برای «خودتان» — هیچ‌چیز منتشر نمی‌شود
```

کارت و کپشن در چت خصوصی ربات می‌رسد. اگر همه‌چیز درست بود — چک‌لیست قبل از تأیید:

- [ ] نام دو تیم و تاریخ جلالی درست است؟
- [ ] تاریخ/ساعت به وقت تهران درست است؟
- [ ] اعداد xG با منبع (football-data.co.uk) هم‌خوان است؟
- [ ] احتمال‌های ۱X۲ جمعشان ~۱۰۰٪ است؟

انتشار واقعی (با تأیید انسانی — ارسال مستقیم ممنوع است، D11):

```powershell
python run.py publish --post-id 1
```

پیام بازبینی با سه دکمه به چت شما می‌آید: **✅ تأیید و انتشار** (→ کانال)،
**❌ رد**، **✏️ ویرایش**. دکمهٔ تأیید را بزنید — پست در کانال می‌رود و
`publishing_logs` ثبت می‌شود.

> ربات polling برای دکمه‌ها: `python -m src.xgpedia.publishers.telegram_bot`
> (در پنجرهٔ جدا باز نگه دارید؛ فقط همان‌جا دکمه‌ها کار می‌کنند). اگر پنجرهٔ
> ربات بسته باشد، همیشه CLI جایگزین دارد:
> `publish --post-id N` (صف) و تأیید از طریق دکمه یا `python -m src.xgpedia.publishers.telegram_bot`.

## روزهای ۱ تا ۷ — روال روزانه (۱۰ دقیقه در روز)

| چه وقت | چه کار | دستور |
|---|---|---|
| صبح | زنجیرهٔ روزانه | `daily-sync.bat` (یا `python run.py daily`) |
| صبح | کنترل خروجی | همهٔ خط‌ها `OK` باشند؛ اگر `[DONE-WITH-ERRORS]` دیدید → پیام `failed` را بخوانید (دستور بازیابی دستی همان‌جا چاپ می‌شود) |
| صبح | تأیید پست‌ها | `list-posts` → `publish --post-id N` → دکمهٔ ✅ |
| هر پست | چک‌لیست داده (بالا) | — |
| اشتباه داده‌ای | رویهٔ اصلاحیه | `docs/corrections.md` (ویرایش + ثبت + علت) |

**قاعدهٔ توقف (خودتان را مقید کنید):** دو خطای مهم داده‌ای در ۷ روز = توقف
انتشار خودکارِ آن دسته تا ریشه‌یابی. خطای مهم = عدد/نام/تاریخ غلطِ دیده‌شده
در کانال، نه خطای فنیِ قابل‌بازیابی (آن‌ها در خروجی daily دستور بازیابی می‌دهند).

## روز ۷ — گزارش هفتگی

```powershell
python run.py weekly-report
```

گزارش در `docs/weekly/week-<شروع>_<پایان>.md` ذخیره می‌شود: پست‌ها بر اساس
وضعیت، ارسال‌های موفق، خطاهای مهم، تصمیم‌های ادمین و رأی نهایی. اگر رأی ⛔
توقف بود → قبل از هفتهٔ دوم، ریشه‌یابی کنید. **همین گزارش، سند عبور از
دروازهٔ ۳ است.**

## عیب‌یابی

| پیام خطا (انگلیسی در کنسول) | معنی | راه‌حل |
|---|---|---|
| `TELEGRAM_BOT_TOKEN is empty` | `.env` پر نشده | گام ۴ روز صفر |
| `bot token rejected (getMe): Unauthorized` | توکن غلط/ناقص کپی شده | توکن را از BotFather دوباره بگیرید |
| `channel not found (getChat)` | آیدی کانال غلط، یا ربات ادمین کانال نیست | گام ۲ و ۳ روز صفر |
| `bot is only a member` / `Administrators -> Add admin` | ربات عضو است ولی ادمین نیست | کانال → Administrators → Add admin |
| `admin N not reachable ... send /start` | شما هنوز ربات را start نکرده‌اید | گام ۵ روز صفر |
| `review could not be delivered to any admin` | هیچ ادمینی ربات را start نکرده | گام ۵ |
| `post N already published (idempotency)` | این پست قبلاً منتشر شده — خطا نیست | پست بعدی را publish کنید |
| `no rendered card for post N` | کارت هنوز رندر نشده | `python run.py render-post --post-id N` بعد دوباره publish |
| `[WARN] Telegram not configured` (daily) | توکن/ادمین در `.env` نیست — کارت‌ها در `output/` مانده‌اند | `.env` را پر کنید؛ daily دوباره (idempotent است، پست تکراری نمی‌سازد) |
| `[WARN] data is stale (13 days > 4)` | آخرین بازیِ انجام‌شدهٔ CSV قدیمی است — **در وقفهٔ ملی طبیعی است** (بازی‌ای انجام نشده) | کاری لازم نیست؛ بعد از اولین هفتهٔ بازی، CSV به‌روز و WARN خودش می‌رود |
| `FAIL - fdo:…: ReadTimeout` یا `503 Service Unavailable` (از سرویس LLM) | خطای گذرای سرویس مدل زبانی — کد شما سالم است | از v0.11.2 خودکار تا ۳ بار با فاصلهٔ نمایی تلاش می‌شود (D30)؛ اگر باز هم FAIL شد: `python run.py daily` دوباره — idempotent است و فقط بازی‌های بدون پست را دوباره می‌سازد |
