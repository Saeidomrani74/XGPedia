## Context

طراحی جدید کارت پیش‌بازی (فایل استودیوی داده‌شده) باید «عیناً» در پروژه کارگزاری شود و با سیستم موجود (draft_json + fact_json + brand.json + DB) هماهنگ شود. بخش عمده همین حالا انجام شده (کپی استودیو، فونت‌ها، هویت تیم‌ها، Dixon-Coles، فیلدهای جدید فکت، بازنویسی cards.py و قالب، اسموک‌تست موفق). این طرح **مراحل باقی‌مانده** را می‌بندد: لوگوی تیم‌ها، تست‌ها، رندر واقعی + بازبینی بصری، رودمپ دارایی‌های آینده، و به‌روزرسانی مستندات.

## مراحل باقی‌مانده

### ۱) `tools/fetch_crests.py` — دانلود لوگوی ۲۰ تیم (ابزار مستقل، بدون وابستگی به پروژه)
- نگاشت canonical نام تیم → نام فایل SVG در Wikimedia Commons (`Special:FilePath/<name>.svg`، UA مناسب، timeout، skip اگر موجود)
- خروجی: `brand/crests/{CODE}.svg` — اولویت SVG (خواستهٔ کاربر: نسخهٔ باکیفیت‌تر)؛ اگر SVG نبود PNG همان کد ذخیره می‌شود و `team_crest_path` خودش svg-اول می‌گزیند
- اجرا برای ۲۰ تیم؛ فایل‌های خراب (HTML error page) حذف و گزارش‌شوند
- اثر در رندر: با یک دست اجرا، نشان انتزاعی (ساخته‌شده از رنگ + کد) جای خود را به لوگوی رسمی می‌دهد — `cards.py::_crest_html` از قبل آماده است

### ۲) به‌روزرسانی تست‌ها (`tests/test_render_cards.py` + فایل جدید `tests/test_analytics_dc.py`)
- بازنویسی تست‌های context قدیمی به شکل جدید (`hero`, `module_data`, `home.color` به‌جای `metrics/home_color/colors`)
- تست‌های حفظ‌شده: جلالی/ساعت تهران، `fmt_stat`/`fmt_fixed`، null≠0، جاسازی فونت (۶ فونت)، بدون رنگ هاردکد در قالب (فقط مقادیر matchday_palette + رنگ تیم از team_identities)
- تست‌های جدید: `dixon_coles_matrix` (نرمال‌بودن مجموع ۱X۲، monotonic O2.5)، `display_colors` (تماس قرمز×زرد → ثانویه؛ Chelsea×قرمزها → ثانویه؛ Fulham×Leeds سفید×سفید → fallback آبی)، `_select_modules` (smart فقط ماژول‌های دارای داده)، سازگاری کدهای team_identities با glossary_fa.json (۲۰ تیم)
- تست sync helpers جدید روی DB واقعی (یک fixture خوانده‌شده: `_team_xg_series`, `_team_form_sequence`, `_team_xga_avg`)
- اجرای کل مجموعه: `python -m pytest tests/ -v` — انتظار: همه سبز

### ۳) `run.py` — دو فلگ اختیاری برای render-post
- `--format {4:5,9:16,16:9}` (پیش‌فرض 4:5) و `--layout {smart,v1,v2,v3}` (پیش‌فرض smart) → پاس به `render_preview_card` (امضای موجود از قبل این پارامترها را می‌پذیرد؛ فقط CLI بند شود)

### ۴) رندر واقعی + بازبینی بصری
- رندر سه فرمت از پست موجود (post_id=1 از DB) و پست نمونهٔ آرسنال×لیورپول با فیلدهای جدید → `output/`
- بازبینی PNG: انطباق چیدمان با استودیو (هدر/هاب VS/کپسول/ماژول‌ها/فوتر) و خوانایی فارسی

### ۵) `docs/ROADMAP.md` + اشاره در README
- وضع موجود: چه داریم (xG/xGA/SOT/فرم/روند۱۰گانه/پواسون/سیگنال)
- دارایی‌های تولیدی/خریدنی آینده با ماژول آماده در قالب: رادار صدک‌ها، مهرهٔ کلیدی + کارت بازیکن، هشدار اختصاصی تیم (watchout)، موج ۱۵دقیقه‌ای (دیتای رویدادی)، badgeهای +EV (دادهٔ ضریب بوک‌میکر)، مربی/جملهٔ زیرنام تیم، ورزشگاه/پخش زنده، هفتهٔ بازی (matchday)
- مراحل درخواستی کاربر: ① تولید آیکون/لوگوهای مورد نیاز (شخصی‌سازی بیشتر لوکاپ برند + فاوآیکون‌ها) ② کارت بازیکن (قالب جدید از همین پالت) ③ عکس بازیکنان (منبع و لایسنس: API-Football پولی / فوتومتر / 手动) — هرکدام با ماژول رندر مستقل
- پاسخ سؤال «کارت‌ها کجا ذخیره می‌شوند» در README (بخش رندر): `output/` در ریشه (قابل تغییر با `--out`)، نام فایل: `post_{id}_v{ver}_{type}_{W}x{H}.{png|jpeg}` + کپشن `.txt` + HTML میانی

## راستی‌آزمایی

1. `python -m pytest tests/ -v` — همهٔ تست‌ها سبز
2. `python tools/fetch_crests.py` → ۲۰ فایل در `brand/crests/` (گزارش skip/fail شفاف)
3. `python run.py render-post --post-id 1 --format 4:5` و `--format 9:16` → PNG سالم در `output/`، بازبینی چشمی نهایی
4. مرور نهایی diff قالب با `tools/matchday_studio.html` برای انطباق عینی طراحی
